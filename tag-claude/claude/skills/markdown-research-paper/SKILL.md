# Markdown → Research Paper PDF

## Overview

Renders a Markdown file as a research-paper-style PDF using
pandoc + xelatex. The skill is a thin, opinionated wrapper:

- `scripts/md2pdf.sh` runs pandoc with the right flags.
- `assets/header.tex` is included as `--include-in-header`
  to patch the usual pain points (code overflow, graphics,
  table packages).
- Metadata (title, author, abstract, bibliography, CSL,
  fonts) comes from YAML frontmatter in the `.md` file, not
  from script flags. That keeps the script simple and the
  source file self-contained.
- An AI disclaimer footnote is forced onto the first page of
  every build, and the byline falls back to a default when
  the frontmatter omits one. See "Author and disclaimer".

Output layout: standard LaTeX `article` class,
single-column, 1.25" margins, colored links. Title, author,
date, and abstract are produced by `\maketitle` in the usual
article style, with the AI disclaimer hanging off the title
as a first-page footnote.

## Inputs

Ask Andrew for these if not obvious from the request:

1. **Input `.md` file(s)** — one or more markdown sources,
   in the order they should appear in the final PDF. YAML
   frontmatter on the **first** file drives document
   metadata (title, author, abstract, bibliography, CSL).
   Frontmatter on any subsequent file is stripped and
   ignored.
2. **Output path** (optional, `-o <path>`) — defaults to
   `<first-input>.pdf` in the same directory.
3. Whether there's a `.bib` file in play, and which CSL to
   use if so. If Andrew says "just use IEEE" or similar,
   he'll need a corresponding `ieee.csl` (or the CSL he
   wants) on disk and referenced from the frontmatter — this
   skill does not bundle one.

## Quickstart

Single file:

```bash
/path/to/markdown-research-paper/scripts/md2pdf.sh paper.md
```

Writes `paper.pdf` next to the source.

Multiple files (e.g. the research procedure's REPORT): each
input after the first is prefixed with a `\newpage` so it
starts on a fresh page.

```bash
/path/to/markdown-research-paper/scripts/md2pdf.sh \
    README.md NOTES.md QUESTION.md \
    -o REPORT_myproject.pdf
```

The first file must carry a YAML frontmatter block with at
least `title` (see below); later files should not have
frontmatter, and any they do have is stripped before
concatenation.

## YAML frontmatter conventions

The `.md` file should start with a YAML block. Typical
fields:

```yaml
---
title: "On the Aesthetics of Research Paper Layouts"
# Byline: the authoring model fills in its own name as MODEL.
author: "Claude (Opus 4.8) under direction of Andrew McAllister"
date: 2026-04-20
abstract: |
  A short abstract. Multiple paragraphs work — use the literal-block
  scalar (`|`) so newlines are preserved.
bibliography: refs.bib    # relative to the .md file
csl: ieee.csl             # relative to the .md file; optional
mainfont: "EB Garamond"   # optional; any system font available to xelatex
monofont: "JetBrains Mono"  # optional
---
```

`--citeproc` is already passed by the wrapper, so
`bibliography:` and `csl:` just work. Omit them if the paper
has no citations. Don't set `thanks:` — it is reserved for
the auto-added AI disclaimer (see "Author and disclaimer").

## Author and disclaimer

**Author.** The byline comes from the first file's `author`
frontmatter. Per the research procedure, use the form
`Claude (MODEL) under direction of Andrew McAllister`, where
the authoring model fills in its own name (e.g. `Opus 4.8`)
— the model writing the report knows which model it is. If
the frontmatter omits `author` entirely, the wrapper falls
back to `Claude under direction of Andrew McAllister` (no
model — the standalone script can't know which model is
running) so the byline is never blank.

**Disclaimer.** Every build gets a first-page footnote
reminding readers that AI output can be wrong:

> This report was generated by an AI system (Claude) under
> human direction. AI can make mistakes and may fabricate
> facts, figures, or citations — verify independently before
> relying on it.

It is wired in as the title's `\thanks` footnote and forced
via `-M thanks=...`, so it always appears and overrides any
`thanks` in the source. Edit the `DISCLAIMER` string in
`scripts/md2pdf.sh` to change the wording.

## Figures

Markdown image syntax renders as a standard `figure`.

```markdown
![A caption.](plots/convergence.png){#fig:conv width=100%}
```

For finer control over placement or sizing, drop a raw
LaTeX `figure` block directly into the markdown where you
want it:

```latex
\begin{figure}[t]
\centering
\includegraphics[width=\textwidth]{plots/big-heatmap.png}
\caption{A full-width figure.}
\label{fig:big}
\end{figure}
```

## Tables

Pipe tables in markdown render via pandoc's default
`longtable` output with `booktabs` rules
(`\toprule`/`\midrule`/`\bottomrule`). `longtable` breaks
gracefully across a page boundary when a table is long.

For anything pandoc's markdown tables can't express
(multi-row headers, row or column spans, multi-paragraph
cells), write raw LaTeX directly in the markdown — a
`\begin{table}...\begin{tabular}...` block, same pattern as
the raw-LaTeX figure above.

## Bibliography and citations

Write citations in pandoc-markdown style:

```markdown
Earlier work established the basic result [@doe2019; @smith2020, pp. 3-5].
```

Keys match entries in the `.bib` file referenced from the
frontmatter. The References section is appended
automatically by `--citeproc`. If Andrew wants the heading
to say something other than "References", add
`reference-section-title: "Bibliography"` to the
frontmatter.

## Code blocks

Handled via pandoc's default skylighting highlighter
(`--syntax-highlighting=tango`). `assets/header.tex`
redefines pandoc's `Highlighting` environment via `fvextra`
to wrap long lines at `\footnotesize`. If code still
overflows, the usual culprits are:

- A single unbreakable token longer than column width (rare;
  manually wrap the source or widen the column).
- A very long URL — wrap it with `\url{}` or break it
  manually.

To change highlight theme, edit the `--syntax-highlighting`
flag in `scripts/md2pdf.sh`.
`pandoc --list-highlight-styles` shows the options.

## Customization

Most tweaks live in one of two places:

**`scripts/md2pdf.sh`** — edit flags here to change:

- `-V geometry:margin=...` — page margins.
- `-V classoption=twocolumn` — add for a two-column layout.
- `--syntax-highlighting=...` — code theme.
- `DISCLAIMER` — the first-page AI disclaimer footnote text.
- Add `--number-sections` for numbered section headings.

**`assets/header.tex`** — edit the LaTeX preamble to change:

- Code block font size or wrapping behavior.
- Any additional `\usepackage{}` directives.

Leave both files alone for the default case.

## Dependencies

- `pandoc` (3.x recommended)
- TeX Live with `xelatex` and the packages loaded by
  `assets/header.tex`: `fvextra`, `geometry`, `tabularx`,
  `booktabs`, `graphicx`, `hyperref`, and `longtable` (used
  by pandoc's markdown tables). All of these are in a
  standard MacPorts `texlive-latex-extra` install.
- A Citation Style Language file (`.csl`) if citations are
  used. Grab what's needed from
  <https://github.com/citation-style-language/styles>.
